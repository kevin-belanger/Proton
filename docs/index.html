Proton

Build a Windows desktop application with HTML, CSS and JavaScript — and ship it as one .exe.

You write an ordinary web application. Proton runs it in a real window, gives it access to files and a SQLite database, and packs the whole thing — engine, interface and all — into a single executable your users can double-click.

No installer. No Node.js. No .NET runtime to deploy. One file.

What it adds to a web page

A page in a browser

  • Cannot read or write files
  • Storage limited to the browser
  • Lives inside tabs and toolbars
  • Needs a server to be served

The same page in Proton

  • Reads and writes real files
  • Queries a local SQLite database
  • Its own window, its own icon
  • Everything inside the executable

Nothing else changes. Your HTML, your CSS, your framework if you use one — all of it works as it does in a browser, because it is a browser: Proton uses the WebView2 engine that Windows already ships.

Getting started

  1. Download Proton.exe

    From the releases page. Put it in an empty folder.

  2. Run it

    A window opens on a starter page that checks the engine's services and links back here. Proton has created an app folder next to itself, holding that page, and a data folder for everything your application will store. 

    MyApp/
├── Proton.exe
├── app/            your web application
└── data/
    ├── files/      your files
    └── db/         your SQLite databases

  3. Replace app with your own

    app/index.html is served at /. Proton reads the folder from disk on every start, so editing a file and reopening the window is the whole development loop — there is no build step and nothing to compile.

The APIs

Three of them, all reached with plain fetch and relative URLs. There is no library to install and nothing to import.

Files

await fetch('/files/notes.txt', { method: 'PUT', body: 'hello' });

const text = await (await fetch('/files/notes.txt')).text();

const { entries } = await (await fetch('/files/reports/')).json();
// [{ name: 'march.pdf', type: 'file', size: 48210, lastModified: '...' }]

await fetch('/files/reports/', { method: 'PUT' });                  // create folder
await fetch('/files/reports/?recursive=1', { method: 'DELETE' });   // and its contents

The trailing slash is what tells a folder from a file. Uploading is a PUT whose body is the content itself — a string, a Blob, or a File straight out of an <input type="file">. Everything under /files lives in data/files, and nothing outside it can be reached.

SQLite

await fetch('/api/sqlite/app.db/execute', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        sql: 'INSERT INTO notes (text) VALUES ($text)',
        parameters: { $text: 'hello' }
    })
});

Reading uses /query and answers with columns and rows kept apart, so that two columns of the same name stay distinct: 

{ "columns": ["id", "name"], "rows": [[1, "Alice"], [2, "Bob"]] }

app.db is created by the first write, in data/db — so open with your CREATE TABLE IF NOT EXISTS, since querying a database that does not exist yet answers 404 rather than inventing an empty one. /transaction takes a list of statements and applies all of them or none, and named parameters mean you never concatenate values into SQL.

Identity

const app = await (await fetch('/api/app')).json();
// { name: "My App", version: "1.0.0", company: "...", engine: { ... } }

Your application reads its own name and version from the executable, instead of repeating them in your code where they drift out of date.

Shipping one file

Write a config/config.json — two properties are enough — and drop an icon beside it: 

{
  "name": "My App",
  "executableName": "MyApp"
}
Proton.exe /config

You get MyApp.exe: the same engine, carrying your name, your icon, your Windows file properties and your application inside it. Proton.exe is left untouched.

Your application is never unpacked onto the disk. It is served from within the executable, so a new version of your program always ships the interface that belongs to it. The two cannot drift apart.

Distribute that single file. On first run it creates its data folder beside itself and starts. To ship starter content — templates, a catalogue, a pre-filled database — put it in data and add the data argument: 

Proton.exe /config data

That content is laid down on first run, and only if data does not already exist. What your users have made is never touched.

Walkthrough: package the sample app

Proton Todo is a complete application — tasks in SQLite, file attachments on disk, drag and drop. Turning it into a program of its own takes about a minute.

  1. Get the sample

    Clone the repository, or download it as a ZIP and unpack it.

    git clone https://github.com/kevin-belanger/Proton.git

  2. Set up a folder

    Copy samples/Todo/app and samples/Todo/config next to Proton.exe: 

    Workshop/
├── Proton.exe
├── app/            index.html, css/, js/
└── config/         config.json, icon.ico

  3. Try it first

    Double-click Proton.exe. Proton Todo opens. Add a task, drop a file onto its card, tick it off — it is already working.

  4. Package it

    From a command prompt in that folder:

    Proton.exe /config

    Proton reports what it embedded and what it wrote, and finishes on the name and size of the file it produced — ProtonTodo.exe, about 63 MB.

  5. Ship it

    Copy ProtonTodo.exe anywhere — another folder, a USB stick, another machine. Nothing else goes with it. Run it: your icon in the taskbar, your name in the title bar, the application working from the first click.

What Proton does not do

Worth knowing before you build on it. Proton is meant for local desktop applications, and it is honest about its edges.

  • Windows only. 64-bit Windows 10 or 11.
  • One window. No multi-window applications.
  • No system access beyond files and databases. No registry, printers, devices or shell commands.
  • No automatic updates. Shipping a new version means shipping a new executable.
  • Local by design. The server listens on 127.0.0.1 only and cannot be reached from the network. It carries no authentication, because there is nobody else to authenticate.

Requirements. Microsoft Edge WebView2, which ships with Windows 11 and with recent Windows 10 installs. No .NET runtime is needed — it travels inside the executable, which is why the file is around 63 MB.
