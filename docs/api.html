API reference

Three APIs, all reached with plain fetch on relative URLs. There is no library to install and nothing to import.

SpaceWhat it holdsOn disk
/files Your application's files and folders data/files
/api/sqlite SQLite databases data/db
/api/app The application's own identity inside the executable
everything else Your application itself app/, or embedded

/files and /api are reserved: a file at app/api/x.html can never capture those routes. Anything under them that Proton does not implement answers 501 rather than falling through to your application.

Files

Everything under /files lives in data/files, and nothing outside it can be reached. The trailing slash is what distinguishes a folder from a file — that one convention explains most of the API.

RouteDoes
GET /files/{path}Read a file
GET /files/{path}/List a folder
PUT /files/{path}Write a file, creating parent folders
PUT /files/{path}/Create a folder (idempotent)
DELETE /files/{path}Delete a file
DELETE /files/{path}/Delete an empty folder
DELETE /files/{path}/?recursive=1Delete a folder and its contents

HEAD is accepted wherever GET is. Any other method answers 405 with an Allow header.

Reading a file

const text = await (await fetch('/files/notes.txt')).text();
const blob = await (await fetch('/files/photo.png')).blob();

The response carries a Content-Type guessed from the extension, Content-Length, Last-Modified and an ETag. Send that ETag back as If-None-Match and an unchanged file answers 304 with no body.

Add ?download to make the browser treat the response as an attachment rather than displaying it — the Content-Disposition header is set for you.

Listing a folder

const { path, entries } = await (await fetch('/files/reports/')).json();
{
  "path": "reports",
  "entries": [
    { "name": "2026",     "type": "directory", "size": null,  "lastModified": "2026-08-25T13:40:41Z" },
    { "name": "march.pdf", "type": "file",     "size": 48210, "lastModified": "2026-08-24T09:12:03Z" }
  ]
}

Folders come first, then names in case-insensitive order — a stable order, so a listing does not reshuffle itself between refreshes. size is null for a directory. Requesting a folder without the trailing slash answers 301 to the canonical form rather than 404.

Writing a file

The body is the content — a string, a Blob, or a File straight out of an <input type="file">. No multipart encoding, no wrapper object. 

await fetch('/files/notes.txt', { method: 'PUT', body: 'hello' });

// Straight from a file input
await fetch(`/files/attachments/${file.name}`, { method: 'PUT', body: file });

Answers 201 when the file is new, 204 when it replaced one, and returns the new ETag. Missing parent folders are created.

Folders

await fetch('/files/reports/', { method: 'PUT' });                  // create
await fetch('/files/reports/?recursive=1', { method: 'DELETE' });   // delete with contents

Deleting a non-empty folder without ?recursive answers 409 and deletes nothing: destroying content should never be the result of an oversight. Symbolic links are removed as links — the deletion never descends into what they point at.

data itself cannot be deleted (403): its contents belong to your application, its existence does not.

SQLite

Databases live in data/db and are reached by name. Three actions, all POST:

RouteDoes
POST /api/sqlite/{db}/queryRead — returns columns and rows
POST /api/sqlite/{db}/executeWrite — returns rows affected
POST /api/sqlite/{db}/transactionSeveral statements, all or none

{db} may contain folders — /api/sqlite/archive/2026.db/query is valid — as long as it stays inside data/db. A GET on this space answers 405: that is the route confirming it is there, not a fault.

Writing

await fetch('/api/sqlite/app.db/execute', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        sql: 'INSERT INTO notes (text) VALUES ($text)',
        parameters: { $text: 'hello' }
    })
});

// → { "rowsAffected": 1, "lastInsertRowId": 7 }

The database is created by the first write. Open with your CREATE TABLE IF NOT EXISTS — querying a database that does not exist yet answers 404 rather than inventing an empty one.

Reading

const { columns, rows } = await (await fetch('/api/sqlite/app.db/query', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ sql: 'SELECT id, name FROM people WHERE age > $min',
                           parameters: { $min: 18 } })
})).json();

// { "columns": ["id", "name"], "rows": [[1, "Alice"], [2, "Bob"]] }

Columns and rows are kept apart rather than merged into objects, so two columns of the same name stay distinct — which an object would silently collapse.

Transactions

await fetch('/api/sqlite/app.db/transaction', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        commands: [
            { sql: 'UPDATE accounts SET balance = balance - $n WHERE id = $a',
              parameters: { $n: 100, $a: 1 } },
            { sql: 'UPDATE accounts SET balance = balance + $n WHERE id = $b',
              parameters: { $n: 100, $b: 2 } }
        ]
    })
});

All of them are applied, or none. The response reports the totals: { "rowsAffected": 2, "lastInsertRowId": 0 }.

Parameters and types

Named parameters mean you never concatenate values into SQL. JSON types map directly:

JSONSQLite
"text"TEXT
42 / 3.14INTEGER / REAL
true / falseINTEGER 1 / 0
nullNULL
{ "base64": "SGVsbG8=" }BLOB

Binary values travel both ways as { "base64": … } — a BLOB read back from a query arrives in that same shape.

ATTACH is disabled. A database can only ever be the one named in the URL, so a statement cannot reach across into another file on the disk. VACUUM INTO relies on the same mechanism and is therefore unavailable too — copy the .db file through /files if you need a backup.

Identity

const app = await (await fetch('/api/app')).json();
{
  "name": "Inventory Manager",
  "windowTitle": "Inventory Manager — 2026 Edition",
  "version": "2.4.1",
  "company": "Kevin's Workshop",
  "engine": {
    "name": "Proton",
    "version": "1.0.0",
    "license": "MIT",
    "copyright": "Copyright (c) 2026 Kevin Belanger"
  }
}

Your application reads its own name and version from the executable, instead of repeating them in your code where they drift out of date. Read-only — anything but GET or HEAD answers 405.

On the plain engine, version and company are null: they only exist for an executable produced by /generate. engine is always present, and carries the MIT attribution the licence requires.

Errors

Every failure answers with the same envelope. The code is stable and meant for your program; the message is for humans and may change. 

{
  "error": {
    "code": "directory_not_empty",
    "message": "The directory is not empty. Add ?recursive=1 to delete its contents.",
    "details": { "path": "reports" }
  }
}
StatusCodeWhen
400invalid_requestBody is not valid JSON, or sql is missing
403invalid_pathThe path leaves data, or holds invalid characters
404not_foundNo such file, folder, database or action
405method_not_allowedWrong method — an Allow header says which are accepted
409directory_not_emptyDeleting a non-empty folder without ?recursive
409not_a_file / not_a_directoryA file sits where you addressed a folder, or the reverse
422sql_failedSQLite refused the statement — its own message is passed through
500read_failed / write_failed / delete_failedDisk full, file locked, permissions
501not_implementedA reserved route Proton does not implement
500unexpected_errorAnything that escaped the rest — written to the log

A 422 carries SQLite's own error text — no such table, syntax error — plus its sqliteErrorCode in details. A 500 reports only the exception type, never a physical path: your application reasons in paths relative to data and has no business knowing where that sits.

Limits and behaviour

  • Request bodies are unlimited on /files — an upload streams straight to disk. /api is capped at 32 MB, since those bodies are parsed in memory.
  • No concurrency control. A Proton application is local and single-instance; last write wins.
  • No origin restriction. The server listens on 127.0.0.1 only, so anything that could reach it is already running on the machine.
  • Paths are confined to data. Traversal (../), absolute paths, drive letters and UNC paths are rejected with 403 before anything touches the disk.
