Getting started

From an empty folder to a working desktop application, then to an executable you can hand to someone else.

Your first run

  1. Download Proton.exe

    From the releases page. Put it in an empty folder. Nothing to install.

  2. Run it

    A window opens on a starter page that checks the engine's services. Proton has created three folders beside itself: 

    MyApp/
├── Proton.exe
├── app/            your web application
├── config/         config.json + icon.ico, for packaging later
└── data/
    ├── files/      served at /files
    └── db/         your SQLite databases

    config arrives filled in and ready — a commented config.json and Proton's own icon, both meant to be replaced. You can run Proton.exe /generate right now and get a working MyApplication.exe. Executables you produce never create that folder: it is a tool for building, not for using.

  3. Replace app with your own

    app/index.html is served at /, and everything below it keeps its path: 

    app/index.html      →  /
app/css/style.css   →  /css/style.css

    Proton reads the folder from disk on every start, so editing a file and reopening the window is the whole development loop. There is no build step and nothing to compile.

Proton never overwrites your files. The starter page is only written when app holds no index.html at all. Once yours is there, it stays.

Developing against the APIs

Everything goes through fetch on relative URLs. A minimal application that writes a file and reads it back: 

<input id="text">
<button id="save">Save</button>
<pre id="out"></pre>

<script>
save.onclick = async () => {
    await fetch('/files/note.txt', { method: 'PUT', body: text.value });
    out.textContent = await (await fetch('/files/note.txt')).text();
};
</script>

That file lands in data/files/note.txt, next to the executable, and survives restarts. See the API reference for folders, listings, databases and error handling.

Debugging

The Proton window has no developer tools: F12 and the context menu are disabled, because an application window is not a browser. While developing, open the same address in Edge or Chrome instead — the server is an ordinary local HTTP server, and everything works there, DevTools included.

When something fails before the window appears, Proton writes what it can to %LOCALAPPDATA%\Proton\logs\proton.log.

Walkthrough: package the sample app

Proton Todo is a complete application — tasks in SQLite, file attachments on disk, drag and drop. Turning it into a program of its own takes about a minute.

  1. Get the sample

    Clone the repository, or download it as a ZIP and unpack it.

    git clone https://github.com/kevin-belanger/Proton.git

  2. Set up a folder

    Copy samples/Todo/app and samples/Todo/config next to Proton.exe: 

    Workshop/
├── Proton.exe
├── app/            index.html, css/, js/
└── config/         config.json, icon.ico

  3. Try it first

    Double-click Proton.exe. Proton Todo opens. Add a task, drop a file onto its card, tick it off — it is already working, before any packaging.

  4. Package it

    From a command prompt in that folder:

    Proton.exe /generate

Source    : C:\Workshop\Proton.exe
Config    : C:\Workshop\config\config.json
Target    : C:\Workshop\ProtonTodo.exe
Icon      : 23,947 bytes
Shift     : -69,632 bytes, 512 padding, 353 offsets rewritten for 351 files
Embedded  : app/ — 4 file(s), 19,829 bytes
Archive   : 7,003 bytes
Verified  : bundle consistent, configuration read back

ProtonTodo.exe generated (62,918,079 bytes).

    Nothing is written until that last line: Proton builds the file under a temporary name, checks that its bundle is intact and that the embedded configuration reads back, and only then puts it in place.

  5. Ship it

    Copy ProtonTodo.exe anywhere — another folder, a USB stick, another machine. Nothing else goes with it. Run it: your icon in the taskbar, your name in the title bar, the application working from the first click.

samples/Todo is worth reading end to end — it is deliberately small, and its README explains why each piece is built the way it is.
